# 2026-10-16

## ★ 屏幕旋转 90°（适配 i.MX6ULL 的 1024x600 横屏）

**需求**：界面是按 600x1024 竖屏设计的，开发板 LCD 是 1024x600 横屏，
显示时高被挤扁。用户要求「把界面逆时针转 90°」。

### 改动（只动 Qt 三个文件，未提交）

| 文件 | 改动 |
|---|---|
| `Qt/main.cpp` | 重写：新增旋转显示层（QGraphicsScene + QGraphicsProxyWidget） |
| `Qt/widget.h` | 加 `designWidth/designHeight()`、`noticeInfo()/noticeConfirm()` |
| `Qt/widget.cpp` | 构造函数改成固定 600x1024；8 处 QMessageBox 换成内嵌提示层 |

- **`main.cpp`**：`Widget` 塞进 `QGraphicsScene`，用 `QGraphicsProxyWidget`
  旋转。坐标反向映射由 QGraphicsView 自动做，不用手算点击位置。
  配置：`--rotate=N` / 环境变量 `JIGUANG_ROTATE` / `kDefaultRotateCcw`（默认 90）。
  填 0 = 不旋转，退回"等比缩小居中"的老行为。
- **`widget.cpp` 构造函数**：原来是「按 availableGeometry 等比缩小」，
  现在改成 `setFixedSize(designWidth(), designHeight())` 固定 600x1024。
  ★ 必须这样 —— 尺寸在旋转前被改掉，转 90° 就凑不出 1024x600。
  缩放逻辑搬到了 main.cpp 的 rot==0 分支。
- **内嵌提示层**：8 处 `QMessageBox::warning/question` 全换成
  `noticeInfo()/noticeConfirm()`（遮罩 QWidget + QFrame 面板 + QPushButton，
  局部 QEventLoop）。原因见下。

### ★★ 三个实测出来的坑（都很反直觉，别再踩）

1. **Qt 的 `QTransform::rotate(+90)` 在屏幕上看是「顺时针」，不是逆时针。**
   我用红/绿/蓝角标记渲染验证过：`rotate(90)` 把界面左上角送到屏幕**右上角**；
   `rotate(270)` / `rotate(-90)` 才送到**左下角**（= 逆时针）。
   → 代码里写的是 `QTransform().rotate(-kDefaultRotateCcw)`，**带负号**。
   （Qt 文档说 "rotates the coordinate system counterclockwise"，
     而坐标系逆时针 = 内容顺时针，所以按直觉写必错。）

2. **板子的 linuxfb 平台插件不支持旋转。**
   `strings libqlinuxfb.so` 里 `rotation` 出现 **0 次**，只有
   `tty= / fb= / size= / mmsize= / offset= / nographicsmodeswitch`。
   → `QT_QPA_PLATFORM=linuxfb:rotation=90` 这招在这块板子上**没用**，
     只能在应用层做。（板子 Qt 是 5.12.9，`/usr/lib/arm-qt`，
     `/etc/profile` 里 `QT_QPA_PLATFORM=linuxfb`，输入走 tslib/evdev。）

3. **把 QMessageBox 用 `setWindowFlags(Qt::Widget)` 变子控件会段错误。**
   Qt 5.8/MinGW 实测：构造正常，`setWindowFlags(Qt::Widget)` 之后进程直接
   段错误（QDialog 的 done()/modality/平台窗口那套在"当子控件"时不成立）。
   → 改成自己搭 `QFrame + QLabel + QPushButton` 面板 + 局部 QEventLoop，
     完全可预期，也不依赖 QDialog。

### 弹窗为什么必须一起处理

`QMessageBox::warning/question` 弹的是**独立顶层窗口**，不在这块
QGraphicsScene 里 → 不跟着旋转 → 竖屏板上会看到歪 90° 的对话框。
所以把遮罩+面板做成 Widget 的**子控件**（子控件天然是界面的一部分）。

- 正式工程 `qmake + mingw32-make` 全新编译：**0 error / 0 warning** ✓
- 另起一个验证台把 Widget 按同样的方式旋转后渲染成 PNG，
  用红/绿/蓝角标记确认方向与几何（90° 后包围盒正好 1024x600，铺满）✓
- 内嵌提示层单独跑了一遍：整屏变暗 + 居中白面板 + 按钮，无崩溃 ✓
- 三个文件行尾全保持 CRLF（`core.autocrlf=true`，无 .gitattributes）✓

### 遗留 / 注意

- **Qt Creator 里用的是 ARM kit（`/opt/fsl-imx-x11/...` SDK），
  本地 MinGW 编译只是语法/告警自检**，真正上板还要用
  `Qt/Jiguang/download.sh` 那套交叉编译 + scp。
- 如果上板后发现转的方向反了，把 `kDefaultRotateCcw` 改成 270 就行
  （或者启动时 `./Jiguang --rotate=270`），不用改结构。
- `QGraphicsView` 比直接画窗口多一层，i.MX6ULL 上软件渲染，
  若监看刷新觉得卡，可以试 `view.setViewportUpdateMode(FullViewportUpdate)`。
- `widget.cpp` 里 `#include <QScreen>` 现在已经没人用了（留着没害处）。

## 第二轮：用户反馈"窗口占满整个屏幕、周边好多空白"

截图里：Windows 桌面上窗口撑满整屏，界面缩在正中间一圈空白。

### 原因：窗口尺寸用了屏幕尺寸

原来写的是 `view.setFixedSize(screen.size())` + `scene.setSceneRect(0,0,屏宽,屏高)`。
板子上屏幕正好 1024x600 看不出来；**桌面上屏 2560x1440 就露馅了** ——
场景和窗口都按整屏开，1024x600 的界面只能缩在中间。

### 改法

- **窗口尺寸 = 旋转后界面自己的包围盒**：`view.setFixedSize(bb.size().toSize())`
  （600x1024 转 90° → 1024x600），`scene.setSceneRect(0,0,bb.width(),bb.height())`。
- 屏幕尺寸**只用来判"装不装得下"和"窗口摆哪儿"**，不用来定窗口大小。
- 屏幕真比界面小才 `t.scale(s,s)` 等比缩小（板子上不会走到）。

### ★★ 顺手抓到的第二个 bug：栈对象双重释放（退出时段错误）

验证时发现进程 **exit=139**（段错误），功能却全对 —— 只在退出时炸。

原因：`QGraphicsScene::addWidget()` 会把控件**所有权**交给
`QGraphicsProxyWidget`，场景析构时会 `delete` 它。
原来写成 `Widget w;`（栈对象），析构顺序 view → scene → w，
scene 析构删一次、w 出作用域又删一次 → 双重释放。

改法：旋转分支里改成 `Widget *w = new Widget;`，所有权交给 proxy，自己不再 delete。
（`rotCcw == 0` 分支仍用栈对象，那条路不进场景。）

改完验证台三种角度全部 **exit=0**。

### 验证

- 验证台把"屏幕"假装成 2560x1440：`VIEW WIN = 1024x600`、`view pos = 768,420`（居中）✓
- 渲染图 1024x600，界面**刚好铺满、无空白边** ✓
- 正式工程全新编译 0 error / 0 warning；三个文件行尾仍 CRLF ✓
