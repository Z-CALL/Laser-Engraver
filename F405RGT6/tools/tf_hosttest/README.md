# tf_fat / tf_image 主机端测试

**不用烧板子**就能验证 TF 卡上"文件系统 + 图像读取"这套逻辑。

## 为什么要有它

`tf_fat.c` 是手写的最小 FAT 解析器，最容易在边界上出错，而硬件往返一次很贵。
这里把 `TF_ReadBlocks()` 桩到一张**本地磁盘镜像**上，用**真源码**跑完整流程：

```
挂 MBR/BPB -> 解析 FAT16/FAT32 -> 扫根目录 -> 跟簇链 -> 读整份 -> 校验 CRC32
```

镜像由 `mkimg.py` / `mkimg32.py` 现场造出来（含 LFN 项、卷标项等干扰项），
所以每次跑都是干净可复现的。

## 用法

```sh
sh run.sh
```

需要 Qt 自带的 mingw gcc（默认用 `C:/Qt/Qt5.8.0/Tools/mingw530_32/bin/gcc.exe`，
可用环境变量 `GCC` 覆盖）。

## 它跑什么

| 用例 | 验什么 |
|---|---|
| FAT16 | 分区偏移 131 + spc=1（一簇一扇区，逼出簇链）+ payload 4970 字节（**不是 512 整数倍**，逼出"尾巴"路径） |
| FAT32 | 32 位 FAT 表项 + 根目录是簇链（不是固定扇区区）+ 高 16 位簇号字段 |
| 512B 环形缓冲 | 缓冲比一次读的扇区还小 → **每个扇区都回绕**，最狠的环形缓冲边界 |

每个用例都验：挂载参数、根目录列举（LFN/卷标必须被跳过）、
大小写不敏感查找、找不到时正确报错、整份 CRC32、按 64 字节"包"取、按单字节取。

## 它抓过什么

- **FAT32 被误判成 FAT16**：`dataSectors = totalSectors - dataStartLba` 里
  `totalSectors` 是分区内扇区数、`dataStartLba` 是绝对 LBA，**基准混了** →
  分区偏移越大簇数算得越少 → 大卡误判成 FAT16 → 簇链按 2 字节项解析 → 读出垃圾。
  （这条已修，`tf_fat.c` 里有注释留档。）
- 文件被截断时能被正确拒绝（`f.size < 16 + total`）。

## 改完 tf_fat.c / tf_image.c 之后

先 `sh run.sh` 跑一遍。全绿再烧板子 —— 能省掉大部分硬件往返。
