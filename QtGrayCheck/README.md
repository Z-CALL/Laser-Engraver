# GrayCheck —— 灰度数组反解 / 回环校验工具

## 这个工具解决什么问题

雕刻出来"一份图变成两份、还错位"这类问题，可能坏在三个地方：

```
   原图 ──[A 上位机]──> 灰度数组 ──[B 串口下发]──> ──[C 固件+机械]──> 纸面
         缩放/灰度/反相/         69字节包/握手/
         低灰度归零/弓字形        行切分/包计数
```

**已经用日志排除了 B**：`固件共请求 800 次，下发 800 包 / 预期 800 包` —— 一个不多一个不少。

**这个工具专门验 A**：把上位机导出的数组**反着走一遍**，看能不能还原出原图。

- 能还原 → A 没问题，问题只可能在 C（固件/机械/方向）
- 不能还原 → A 就有问题，而且还原出来的**错误形状**会直接告诉你坏在哪一步

## 编译

需要 Qt 5.8 + MinGW 32bit（和主工程同一套工具链）。

```powershell
# 注意：本机 PATH 里混了一个 x86_64 GCC，会把 32 位 Qt 链接搞崩，
# 所以先把 PATH 钉死成 Qt 那一套
$env:Path = "C:\Qt\Qt5.8.0\5.8\mingw53_32\bin;C:\Qt\Qt5.8.0\Tools\mingw530_32\bin;C:\Windows\system32;C:\Windows"

qmake GrayCheck.pro -spec win32-g++
mingw32-make -j4
```

产物：`release\GrayCheck.exe`

## 用法

### 图形界面

```
GrayCheck.exe
```

1. 点「打开导出的数组文件(.h/.c/.txt)」，选你在上位机点「导出灰度C数组(二维)」存下来的那个文件
2. 点「打开原图对照」，选同一张原始图片
3. 在中间的视图下拉里切换对比：

| 视图 | 是什么 |
|---|---|
| ① 还原图（原图观感） | 已翻极性 + 反转倒序行 + 逆映射 → **应该和原图一模一样** |
| ② 数组原样（0=黑） | 数组原封不动的样子 → 它是原图的**负片**，用来核对存储顺序 |
| ③ 原图 | 你手动打开的原图 |

右侧是逐项自检报告：尺寸、行数、每行数值个数、方向标记统计、值域、映射情况等。

### 命令行（方便脚本化 / 批量校验）

```
GrayCheck.exe <导出的数组文件> <输出.png>
```

退出码 `0` = 解析成功；`1` = 失败。同时把自检报告打到 stdout。

## 判读表

把「① 还原图」和「③ 原图」并排比：

| 现象 | 说明问题出在 |
|---|---|
| **完全一致** | 上位机链路正常 → 去查固件/机械（方向、细分、行程） |
| 上下颠倒 | 行序反了（数组 y=0 对应的不是图像最上面一行） |
| 左右镜像 | 弓字形反转用错了（奇数行该反没反，或反过来） |
| 错行 / 斜纹 | 行与包的切分错位（宽度不是 64 的整数倍时容易出） |
| 整体反相 | 极性搞反（"黑=255"这条约定被破坏） |
| 只有接近纯白的地方变成黑 | 低灰度归零阈值（`kGrayCutoff`）判在了错误的量上 |

## 自测（round-trip）

`selftest_roundtrip.py` 会：

1. 造几张有辨识度的原图（箭头 / 横向斜坡 / 字母F）
2. **严格复刻** `Widget::buildGrayArrayLines()` 的文本格式，写出导出文件
3. 调 `GrayCheck.exe` 反解成 PNG
4. 用 PIL 逐像素和原图比对

```powershell
python selftest_roundtrip.py <构建目录>
```

**当前结果：6/6 PASS，最大偏差 0**

| 用例 | 弓字形 | 灰度映射 | 结果 |
|---|---|---|---|
| arrow_nobidi | 关 | 无 | PASS 0.00% |
| arrow_bidi | 开 | 无 | PASS 0.00% |
| grah_nobidi | 关 | 无 | PASS 0.00% |
| grah_bidi | 开 | 无 | PASS 0.00% |
| textF_bidi | 开 | 无 | PASS 0.00% |
| textF_map | 开 | 40→200 | PASS 0.00% |

也就是说：**"图像 → 灰度 → 反相 → 截断 → 映射 → 弓字形 → C数组文本" 这一整条链路是可逆的、无损的**（映射那档的往返误差也在 6 个灰阶以内）。

### ⚠ 这个自测的局限（必须知道）

`selftest_roundtrip.py` 里的 `host_pipeline()` 是我**按源码复刻**的，不是调用真实的 `widget.cpp`。
如果我的复刻和真实上位机有偏差，那么这个自测"通过"**不能证明真实上位机没问题**。

**所以真正的判据是拿真实上位机导出的文件跑一遍**（见下面"怎么用它验真实链路"）。

### 自测脚本自己踩过的三个坑（留档，都是测试的错不是代码的错）

1. **漏了反相那一步**：`host_pipeline` 少写 `v = 255 - src`，导致"数组值"和"原图灰度"混为一谈，报出 90% 超差
2. **截断判错了量**：`kGrayCutoff` 判的是**反相后**的值（`val = 255-src; if (val < CUTOFF) val = 0`），
   所以会被归零的是 **src > 255-CUTOFF**（接近纯白）的像素，不是 src < CUTOFF —— 写反了，斜坡图误报 5.5% 超差
3. **`__pycache__` 残留**：改了 `.py` 后同目录还有旧的 `.pyc`，`import` 拿到旧逻辑，现象是"改了代码结果完全不变"

## 怎么用它验真实链路

1. 在上位机里：载入原图 → 记下**图像尺寸**、**弓字形开关**、**灰度映射上下限**
2. 点「导出灰度C数组(二维)」，存成 `xxx.h`
3. 打开 `GrayCheck.exe`，载入 `xxx.h`，再「打开原图对照」选**同一张原图**
4. 设置必须和导出时一致（GrayCheck 从文件表头自动读弓字形/映射，不用手填）
5. 看「① 还原图」和「③ 原图」是否一致

**建议第一次用最难糊弄的图**：纯黑背景上一个白色字母 `F`（或反过来）。
镜像、颠倒、错行在这张图上都是一眼可见的；渐变图反而容易看走眼。
